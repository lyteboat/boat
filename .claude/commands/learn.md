# 规则
1. 先读代码再下结论。关键结论标出处（路径:行号），不必每句都标。
2. 标依据：【代码事实】【文档依据】【我的推断】；标归属：【Cordis】【dsh 原生】【lyteboat 改写】【lyteboat 新增】。
3. 每个概念用一句话给出旧框架里的对应物和差异。统一称“旧框架”，任何地方都不写它的项目名。
4. 宽泛命名用一行澄清：名字 → 所属层 → 实际职责。
5. 只读：不修改、不提交仓库文件。页面 HTML 写在 scratchpad。

# 篇幅（硬性）
- 第一句就是答案。
- 招熟最多三块：一张图、一个例子、一张表（不超过 6 行）。
- 懂劲最多 3 条，每条不超过两句。
- 神明一句。
- 页末：“暂可忽略”一行，“下一步建议阅读的 3 个文件”。
- 正文（不含代码和表格）控制在一屏半以内。写不下说明讲多了：删掉，不要拆成更多小节。
- 追问优先改写已有页面，让它更短更清楚；不要一直往页面末尾追加章节。
